## Sync — `/zilch-knowledge /sync`

**Skill command:** `/zilch-knowledge /sync`

**Purpose:** Fully regenerate the index from the live Confluence space. Rebuilds both the **Top-level pages** table and the **Auto sub-page tree** from scratch. Incremental updates are NOT supported — always a full recreation. The **Project repos** section is **NOT** regenerated by sync — it is hand-curated by the user (auto-discovery via GitLab API is unreliable because the bot token may lack access to key repos).

**When to run:**
- A new top-level page is created
- A top-level page is renamed or deleted
- The sub-page tree has shifted (new pages, renames, deletions)
- Periodic freshness (e.g., quarterly)

**Procedure the skill executes:**

1. **Fetch all pages** from space `458757` via cursor-paginated `getPagesInConfluenceSpace` (limit=100, follow `_links.next` until exhausted).
2. **Classify** each page:
   - `parentId` is null OR parent not in space → **top-level**
   - Otherwise → **sub-page**
3. **For top-level pages:** fetch full content via `getConfluencePage` and produce a 1–2 sentence "Covers" summary. Top-level summaries are hand-curated — the agent drafts, the user reviews and edits before commit.
4. **For sub-pages:** record only metadata (title, ID, parent ID, last-updated date). No body fetch.
5. **Recompute staleness** on top-level pages from current date.
6. **Write** the new `knowledge-index.md` to disk (overwrites existing file completely).
7. **Preserve the Project repos section verbatim** from the prior version — do NOT auto-refresh it.
8. **Show diff** to user for review.
9. **On user approval:** commit (no co-author line) and update `Last indexed` date in the file.
10. **On user rejection:** archive the draft, surface what was wrong, ask for direction.

**What sync does NOT do:**
- Does not fetch page bodies for sub-pages (intentional — keeps the file small)
- Does not write to Confluence (read-only)
- Does not auto-commit — always waits for user approval
- Does not regenerate the Project repos section (hand-curated)

**Edge cases:**
- If the top-level page count changes (new/deleted), update the "Total pages" line and the Topic Clusters section.
- If a parent page moves (becomes a child or vice versa), re-classify and update both tables.
- If Confluence MCP is unavailable, surface the error and ask whether to retry, skip sync, or proceed with the stale index.
- If the user wants to refresh Project repos, that is a separate manual edit — surface as a follow-up task.

## Out-of-scope for this index

- Page body snapshots — never copy page contents here; runtime fetches always

- Editing the top-level "Covers" summaries — the sync command produces drafts; user reviews and edits
